## Pitfalls captured for the next session

### 1. bleak 0.22 API change: `char.properties` is now `Iterable[str]`, not enum objects (2026-07-07)

The first enumerate run connected successfully but blew up at:
```
AttributeError: 'str' object has no attribute 'name'
```
The cause: `bleak` ≥0.22 changed `Characteristic.properties` from `[<CharacteristicPropertyName.read: ...>]` to `["read", "notify", "write"]`. Already patched in `enumerate.py` line 49 (`list(char.properties)` then join). If you upgrade bleak, double-check this — the test is in the **acceptance step 3** above (count must be ≥4).

### 2. Telink smart rings sleep hard between advertisements (2026-07-07)

After the mid-enumerate crash on session 1, the SR16 stopped advertising for the rest of the working time (5+ minutes). Two contributing factors:

- The crash raised **inside** `async with BleakClient(...)`, so the `__aexit__` may have left a half-open GATT session in CoreBluetooth's L2CAP layer
- Telink rings default to a long advertising interval (2–5 minutes) when idle — once you connect and the connection drops ugly, they wait for the next interval tick to re-advertise

Fix attempts to consider in session 2:
- **Wrap connect + enumerate in `try/finally` with `client.disconnect()` even on error** (enumerator already does this, but the AttributeError happened inside `service.characteristics` loop, which is BEFORE any disconnect cleanup; refine the loop structure)
- Add a longer scan fallback (60–120 s) — the prior probe script reports `seen=5` within 1s and stays flat, so a 60s scan doesn't waste much
- **Best fix: don't crash the enumeration** — any unhandled exception aborts the whole loop and leaves CoreBluetooth in a bad state. Wrap each `service.characteristics` iteration in its own try/except so one bad char doesn't break the whole enumeration

### 3. `bleak` `BleakClient` accepts a UUID but prints it raw — normalize the case in DB writes (2026-07-07)

`find_sr16()` stores `device.address` (uppercase, hyphenated) from CoreBluetooth, but `client.services.uuid` is lower-case canonical. Sessions rows vs inventory rows can drift in case. Already normalized in `enumerate.py` (`str(service.uuid).lower()` and `device_uuid` lower-cased) — keep that convention if you add more writers.

## Architectural decisions

### 1. `~/health/sr16.db` lives OUTSIDE the project tree

Why: BLE-app bundles get rebuilt + reinstalled. Anything inside the project risks being wiped by an `rm -rf .build` or a `git clean -fdx`. The DB belongs in user's data area (not `~/Library/Application Support/...` — that requires a bundle ID too; the bare `~/health/` is consistent with how `~/Documents/`, `~/Downloads/`, etc. belong to the user with no app-mediated path).

### 2. bleak via uv venv, NOT pip3 globally

Why: PEP 668 blocks system pip installs on this Mac; bleake's pyobjc-CoreBluetooth dependency is OS-version-sensitive — pinning to a venv isolates future macOS upgrades from breaking system Python.

### 3. PROBE-LOG is append-only, NOT gitignored

It's a permanent experiment log. Every BLE scan + every GATT run goes in as a timestamped markdown block. If we lose the SQLite (corrupt fs, accidentally `rm`), PROBE-LOG remains the engineering record and can seed v2.0.

### 4. Mirror the OG glasses-bridge project layout

Same `src/<pkg>/`, same `sys/` audit folder, same `HANDOFF-<date>.md` pattern. Keeps the muscle-memory transfer cost zero.
